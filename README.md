# SusDevOS

**GHG reporting, ecosystem tracking, and sustainable development management for property and infrastructure projects.**

SusDevOS is a multi-tenant SaaS platform that helps sustainability managers, ESG consultants, and development project managers track Scope 1/2/3 emissions, manage tree removals and habitat restorations, validate carbon credits against Verra/Gold Standard, and produce audit-ready GHG inventory reports — all aligned to GHG Protocol, IPCC, and TNFD.

---

## What's built

### Backend — Django REST API

| Area | Detail |
|------|--------|
| **GHG calculation engine** | Server-side only. `EmissionsData.save()` computes `QuantityOrCost × EmissionFactor × GWP_factor`. Client-submitted amounts are always overwritten. GWP seeded from IPCC AR6 GWP100. |
| **Scope 2 dual method** | Both `EmissionsAmountLocationBased` and `EmissionsAmountMarketBased` always populated. Mandatory for GHG Protocol-conformant inventory. |
| **Verification + immutability** | `VerificationStatus ≥ 3` → PATCH/DELETE blocked (HTTP 403). Unlock requires SuperAdmin + mandatory reason → AuditLog entry with 7-year retention. |
| **Multi-tenancy** | Single-database row-level isolation. All querysets filtered by `EntityId` from the `X-Entity-ID` request header. `EntityId` is never trusted from request bodies. |
| **JWT auth** | 15-min access token + 7-day HttpOnly refresh cookie. Server-side revocation via `RevokedTokens` table (jti UUID). |
| **RBAC** | `Modules → Interfaces → Roles → RolePrivileges → UserPrivilegeOverrides`. 4 roles (SuperAdmin, Admin, Manager, Staff), 13 modules, 49 active interfaces, 56 default role privilege rows. |
| **Feature gates** | `FeatureGateMixin.required_feature` checks `PlanFeatures` table → HTTP 402 `{"code": "feature_gated", "upgrade_url": "/pricing"}`. 5 billing plans, 33 feature keys. |
| **12 Django apps** | shared · entities · users · projects · land · ecosystem · emissions · restorations · notifications · blog · reports · billing |
| **Celery tasks** | ECB FX daily sync · Climatiq/DEFRA EF sync · Verra VCS daily validation · nightly inventory total recomputation · audit log retention purge · report file purge |
| **Admin** | All 12 apps registered with search, filters, inlines, and `raw_id_fields`. |
| **OpenAPI** | drf-spectacular → local-only `GET /api/schema/` (229 KB) · production route catalogue disabled |
| **Tests** | 224 pytest tests covering auth flows, tenant scoping, GHG formula correctness, verification immutability, RBAC privilege resolution, billing entitlement, and Celery task scheduling. |

Customer/developer API access and customer-managed API keys are intentionally unavailable
during the PMF phase. The first-party web application continues to use the protected REST API.

### Frontend — Next.js 14

| Page | What it does |
|------|-------------|
| `/login` | Email or username login. Stores access token in Zustand (memory only); refresh token is HttpOnly cookie. |
| `/forgot-password` | Sends reset link. Always 204 — no email enumeration. |
| `/reset-password` | Consumes one-time token, sets new password. |
| `/onboard` | First-login password set for newly invited users. |
| `/dashboard` | Live Scope 1/2/3 summary cards + recent emissions table + active projects list. Data fetched via TanStack Query. |
| `/emissions` | List with scope filter. Create modal with Scope/Gas/EF fields. Server computes tCO₂e automatically. |
| `/projects` | List + create modal. Phase count shown. |
| `/reports` | Queue report jobs, poll live status, download pre-signed S3 URL. Auto-refreshes every 5 s while jobs are processing. |

**TypeScript API client** generated by orval from the local OpenAPI schema (12,470 lines of typed hooks and schemas in `frontend/src/lib/api/index.ts`).

## Getting started

### Prerequisites

- Docker Desktop 4+
- Node 20+ (for the frontend)

### 1. Start infrastructure

```bash
docker compose up db redis minio -d
```

### 2. Start the backend

```bash
docker compose up api -d
```

On first run, seed the reference data:

```bash
docker compose run --rm api python manage.py migrate
docker compose run --rm api python manage.py seed_superadmins
docker compose run --rm api python manage.py seed_modules
docker compose run --rm api python manage.py seed_gwp
docker compose run --rm api python manage.py seed_plans
```

Then open:
- **Django admin:** http://localhost:8000/admin/ — `superadmin1@susdevos.com` / `ChangeMe!12345`
- **Swagger UI:** http://localhost:8000/api/schema/swagger-ui/

### 3. Start the frontend

```bash
cd frontend
npm install
npm run dev   # http://localhost:3000
```

### 4. Run the tests

```bash
docker compose run --rm api python -m pytest -q
```

Expected: **224 passed**.

## Key domain rules

These are enforced in the code and verified by tests. Do not break them:

1. **Never compute emissions on the client.** `EmissionsAmount` is always server-populated by `EmissionsData.save()`. Client-submitted values are stripped by the serializer.
2. **Never skip `request.entity_id` filtering.** Every queryset involving tenant data is filtered by `EntityId`. `EntityId` is never accepted from request bodies — only from the `X-Entity-ID` header.
3. **Verified inventories are immutable.** `GHGInventories.VerificationStatus ≥ 3` → reject PATCH/DELETE with HTTP 403. Only SuperAdmin can unlock via `POST /emissions/{id}/unlock/` with a mandatory reason.
4. **Biogenic CO₂ is NOT in the GWP total.** It is stored in `BiogenicCO2AmountTonnes` and reported separately.
5. **Scope 2 requires both methods.** Both `EmissionsAmountLocationBased` and `EmissionsAmountMarketBased` are always computed.
6. **Feature gates are server-enforced.** `FeatureGateMixin` on the view is the authoritative check. Never rely on frontend-only gating.

## AI-assisted development safeguards

SusDevOS uses the optional `$susdevos-delegate` Codex skill when a maintainer explicitly requests delegated implementation, investigation, fan-out, or independent review. Delegation does not grant additional authority: production systems, cloud accounts, customer data, credentials, deployments, and external writes remain prohibited unless the user specifically authorizes them.

The skill provides three focused resources:

| Resource | Purpose |
|----------|---------|
| `task-brief-template.md` | Captures the user outcome, authoritative specifications, invariants, scope, non-goals, edge cases, permissions, and exact verification contract. |
| `verification-matrix.md` | Selects independent checks based on the changed area and risk, with additional coverage for tenant isolation, GHG calculations, verified inventories, billing, and migrations. |
| `review-triage.md` | Treats review findings as claims to reproduce or prove before deciding to fix, ask the user, document, or drop them. |

Core safeguards:

1. Read `CLAUDE.md` and the relevant `spec/` source before delegated work begins.
2. Prefer read-only delegation. Give every writing agent an isolated worktree; never run multiple writers in one working tree.
3. Preserve the user's working tree and stabilize shared prerequisite work before creating dependent branches or worktrees.
4. Independently inspect every changed hunk and rerun relevant tests, linting, type checks, builds, and migration checks. A delegate's report is supporting evidence, not verification.
5. Mutation-check critical regression guards—particularly tenant isolation, entitlement, immutability, and emissions calculations—when the risk justifies it.
6. Reproduce consequential review findings and verify their preconditions. Ask before adding storage, jobs, infrastructure, configuration, retry policies, or other product surface.
7. Inspect `git status` and stage explicit paths so temporary or generated delegate files cannot enter commits accidentally.
