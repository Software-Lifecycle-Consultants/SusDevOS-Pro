# SusDevOS

**GHG reporting, ecosystem tracking, and sustainable development management for property and infrastructure projects.**

SusDevOS is a multi-tenant SaaS platform that helps sustainability managers, ESG consultants, and development project managers track Scope 1/2/3 emissions, manage tree removals and habitat restorations, set SBTi targets, and produce audit-ready GHG inventory reports — all aligned to GHG Protocol, IPCC, SBTi, CDP, and TNFD.

---

## What's built

### Backend — Django REST API

| Area | Detail |
|------|--------|
| **GHG calculation engine** | Server-side only. `EmissionsData.save()` computes `QuantityOrCost × EmissionFactor × GWP_factor`. Client-submitted amounts are always overwritten. GWP seeded from IPCC AR6 GWP100. |
| **Scope 2 dual method** | Both `EmissionsAmountLocationBased` and `EmissionsAmountMarketBased` always populated. Mandatory for GHG Protocol-conformant inventory. |
| **Verification + immutability** | `VerificationStatus ≥ 3` → PATCH/DELETE blocked (HTTP 403). Unlock requires SuperAdmin + mandatory reason → AuditLog entry with 7-year retention. |
| **Multi-tenancy** | Single-database row-level isolation. All querysets filtered by `EntityId` from the `X-Entity-ID` request header. `EntityId` is never trusted from request bodies. |
| **JWT auth** | 15-min access token + 7-day HttpOnly refresh cookie. Server-side revocation via `RevokedTokens` table (jti UUID). |
| **RBAC** | `Modules → Interfaces → Roles → RolePrivileges → UserPrivilegeOverrides`. 4 roles (SuperAdmin, Admin, Manager, Staff), 13 modules, 46 interfaces, 56 default role privilege rows. |
| **Feature gates** | `FeatureGateMixin.required_feature` checks `PlanFeatures` table → HTTP 402 `{"code": "feature_gated", "upgrade_url": "/pricing"}`. 5 billing plans, 37 feature keys. |
| **12 Django apps** | shared · entities · users · projects · land · ecosystem · emissions · restorations · notifications · blog · reports · billing |
| **Celery tasks** | ECB FX daily sync · Climatiq/DEFRA EF sync · SBTi registry monthly sync · Verra VCS daily validation · nightly inventory total recomputation · audit log retention purge · report file purge |
| **Admin** | All 12 apps registered with search, filters, inlines, and `raw_id_fields`. |
| **OpenAPI** | drf-spectacular → `GET /api/schema/` (229 KB) · Swagger UI at `/api/schema/swagger-ui/` |
| **Tests** | 85 pytest tests: 37 model tests + 48 API tests covering auth flows, tenant scoping, GHG formula correctness, and verification immutability. |

### Frontend — Next.js 14

| Page | What it does |
|------|-------------|
| `/login` | Email or username login. Stores access token in Zustand (memory only); refresh token is HttpOnly cookie. |
| `/forgot-password` | Sends reset link. Always 204 — no email enumeration. |
| `/reset-password` | Consumes one-time token, sets new password. |
| `/onboard` | First-login password set for newly invited users. |
| `/dashboard` | Live Scope 1/2/3 summary cards + recent emissions table + active projects list. Data fetched via TanStack Query. |
| `/emissions` | List with scope filter. Create modal with Scope/Gas/EF fields. Server computes tCO₂e automatically. |
| `/projects` | List + create modal. Phase count shown. |
| `/reports` | Queue report jobs, poll live status, download pre-signed S3 URL. Auto-refreshes every 5 s while jobs are processing. |

**TypeScript API client** generated by orval from the live OpenAPI schema (11,689 lines of typed hooks and schemas in `frontend/src/lib/api/index.ts`).

### Content Engine — AI-powered marketing workflows

Located in `content-engine/`. Three Claude-powered agents for the SusDevOS marketing team:

| Script | What it does |
|--------|-------------|
| `research.py` | **Weekly research agent.** Monitors 12 RSS feeds (GOV.UK, SBTi, GHG Protocol, CDP, Edie, Carbon Brief, TNFD, UNFCCC, and more). Claude picks the 5 most relevant stories for sustainability managers and produces a ready-to-use content brief with blog angle, LinkedIn hooks, and regulatory calendar. |
| `draft.py` | **Blog draft agent.** Takes a topic (plus optional brief from `research.py`) and writes a complete, SEO-tagged blog post in the SusDevOS brand voice. Optionally publishes directly to Ghost CMS as a draft. |
| `repurpose.py` | **Content repurposing agent.** Takes a finished blog post and produces: a 600–800 word LinkedIn article, 4 short LinkedIn posts, a 7–10 minute YouTube video script with B-roll cues, and YouTube metadata (3 title options, description with chapters, 10 tags). Optionally queues posts to Buffer for scheduled publishing. |

All three agents use `claude-opus-4-5`.

**Quickstart:**
```bash
cd content-engine
pip install -r requirements.txt
cp .env.example .env          # add ANTHROPIC_API_KEY
python research.py            # produces briefs/YYYY-MM-DD.md
python draft.py "Why Scope 3 Category 15 matters for property developers"
python repurpose.py posts/my-post.md --buffer
```

## Getting started

### Prerequisites

- Docker Desktop 4+
- Node 20+ (for the frontend)
- Python 3.12 (for the content engine only — backend runs in Docker)

### 1. Start infrastructure

```bash
docker compose up db redis minio -d
```

### 2. Start the backend

```bash
docker compose up api -d
```

On first run, seed the reference data:

```bash
docker compose run --rm api python manage.py migrate
docker compose run --rm api python manage.py seed_superadmins
docker compose run --rm api python manage.py seed_modules
docker compose run --rm api python manage.py seed_gwp
docker compose run --rm api python manage.py seed_plans
```

Then open:
- **Django admin:** http://localhost:8000/admin/ — `superadmin1@susdevos.com` / `ChangeMe!12345`
- **Swagger UI:** http://localhost:8000/api/schema/swagger-ui/

### 3. Start the frontend

```bash
cd frontend
npm install
npm run dev   # http://localhost:3000
```

### 4. Run the tests

```bash
docker compose run --rm api python -m pytest -q
```

Expected: **85 passed**.

## Key domain rules

These are enforced in the code and verified by tests. Do not break them:

1. **Never compute emissions on the client.** `EmissionsAmount` is always server-populated by `EmissionsData.save()`. Client-submitted values are stripped by the serializer.
2. **Never skip `request.entity_id` filtering.** Every queryset involving tenant data is filtered by `EntityId`. `EntityId` is never accepted from request bodies — only from the `X-Entity-ID` header.
3. **Verified inventories are immutable.** `GHGInventories.VerificationStatus ≥ 3` → reject PATCH/DELETE with HTTP 403. Only SuperAdmin can unlock via `POST /emissions/{id}/unlock/` with a mandatory reason.
4. **Biogenic CO₂ is NOT in the GWP total.** It is stored in `BiogenicCO2AmountTonnes` and reported separately.
5. **Scope 2 requires both methods.** Both `EmissionsAmountLocationBased` and `EmissionsAmountMarketBased` are always computed.
6. **Feature gates are server-enforced.** `FeatureGateMixin` on the view is the authoritative check. Never rely on frontend-only gating.
